## The method

Each major idea is taught in three passes:

1. **From scratch in plain Java.** A minimal implementation with no AI libraries: an autograd engine, a BPE tokenizer, attention, an HNSW index, an agent loop, an MCP server.
2. **With the library.** The same capability through Spring AI, LangChain4j, DJL or ONNX Runtime, and what the library does internally.
3. **In production.** How it looks in a real Spring Boot service: cost, latency, security, observability and governance.

You already have the production instincts. The from-scratch pass gives you the mental model that makes those instincts apply to AI systems.

## Anatomy of a lesson

| Section | Use it to… |
|---|---|
| Why it matters | Decide whether the lesson solves a problem you have |
| Concept | Build the mental model; read the diagram before the prose |
| Build it from scratch | Read the code, then **re-type it without looking** |
| Now with the library | Map the hand-built version onto the framework |
| Production notes | Collect the checklist items for your own projects |
| Exercises | Easy = understanding, Medium = extension, Hard = design |
| Quiz | Check yourself; scores are saved |
| Interview prep | Answer out loud before opening the model answer |

## A study plan for an experienced engineer

You can move faster than a beginner, but skipping the math phases makes the later phases shallow. A sustainable plan at **6–8 hours per week**:

| Weeks | Phases | Outcome |
|---|---|---|
| 1–3 | 0–2 | Math and classical ML intuition, all in Java |
| 4–6 | 3–5 | You have built a neural network and a transformer forward pass |
| 7–8 | 6–7 | Fluent with Spring AI, LangChain4j and prompt design |
| 9–11 | 8–9 | Vector search and production-grade RAG, including over Liferay |
| 12–13 | 10–11 | Agents, tool use and MCP servers |
| 14–16 | 12–15 | Evals, fine-tuning decisions, LLMOps, security, governance |
| 17–18 | 16–17 | Architecture case studies and AI delivery leadership |
| 19+ | 18 | Capstones — build, evaluate and present |

## Make it stick

- **Use the tutor as a sparring partner, not an oracle.** It answers from the course content and cites lessons; check its citations.
- **Keep an engineering journal.** One paragraph per lesson: what surprised you, what you would do differently in production.
- **Re-implement, don't re-read.** The from-scratch code is short on purpose. Rebuilding it from memory a week later is the strongest retention technique there is.
- **Tie every phase back to a real system you know.** The hard exercises ask you to.

## Running the lessons

```bash
./mvnw test                                    # all lesson tests
./mvnw -pl lessons/p08-vector-search test      # one phase
./mvnw -pl app spring-boot:run                 # this site, http://localhost:8080
```

Each phase module is a normal Maven module. Open the root `pom.xml` in your IDE and run any `main()` or test directly.
